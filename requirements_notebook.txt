# tfds 4.9.10 needs protobuf>=5, which conflicts with TF 2.13/2.15 (see issue #7).
# tfds<4.9.7 alone isn't enough, though: its tensorflow-metadata dependency
# resolves to a version (>=1.15) whose protoc-generated _pb2.py files import
# `google.protobuf.runtime_version`, which doesn't exist before protobuf 5 —
# that import fails even with protobuf pinned below 5. Pinning
# tensorflow-metadata<1.15 as well keeps its generated code on the older
# protobuf runtime. Verified end-to-end in a clean venv: `import
# tensorflow, tensorflow_datasets` and `tfds.builder("svhn_cropped")` both
# succeed with this exact combination.
tensorflow-datasets>=4.9.0,<4.9.7
tensorflow-metadata>=1.13.0,<1.15.0
protobuf>=3.20.3,<5.0.0
numpy>=1.24.0,<2.0.0
